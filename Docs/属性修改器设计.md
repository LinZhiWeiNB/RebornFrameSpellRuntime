# 属性修改器设计

本文说明修改器如何保存贡献、如何在一次属性批次中结算，以及这些选择针对哪些开销。

通道、公式和调用方式见 [属性修改器](属性修改器.md)。

## 目标

本管线是 Access → Seal → Calc → Apply 架构。

| 阶段 | 执行位置 | 职责 |
| --- | --- | --- |
| Access | 主线程，两次批次之间 | 设置、查询、删除贡献，并维护各通道的当前值。 |
| Seal | 主线程 | 把本批要重算的属性收成连续快照。 |
| Calc | 多个工作线程 | 只读快照，并行计算公式。全部完成后，主线程才进入写回。 |
| Apply | 多个工作线程 | 不同单位并行写回。同一单位的属性在同一个工作项里顺序写入。 |

其余目标：

- 写入时维护每个通道的当前值，Seal 和 Calc 不再遍历贡献。
- 公共方法接收属性 ID。内部按下标访问状态。
- 查询立刻返回已保存的贡献。

一个 World 只有一条 `AttributePipeline`。系统使用 `DisableAutoCreation`，由 `UpdateOnce` 在主线程显式推进。`UpdateOnce` 只运行 Seal、Calc、Apply 以及批次中的请求和事件阶段。Access 不进入这次调用。批次期间不得禁用、销毁或回收已进入流水线的单位。

## 数据

### 状态

`AttributeModifierState` 与单位属性布局等长，下标就是布局槽位。资源、数值和标记属性在 `InitializeUnit` 时各占一格。标记属性的 `BaseBits` 是配置默认值。

状态保存批次需要的热字段：配置基础值、四个 128 位通道合计、三个重载堆顶及其非空标记、值类型、行为、非负限制、资源缩放标记和脏标记。三个重载堆在堆缓冲中的起点和长度也记在状态上。

设置和删除用 `states[slot]` 定位。槽位超出状态长度时写入失败。

### 贡献

`AttributeModifierContribution` 记录一条 `(槽位, Buff 实例 ID, 通道)` 的值和权重。该缓冲的 `InternalBufferCapacity` 为 0，贡献不内联进单位块。

查找一条贡献时，线性扫描该单位的贡献缓冲。替换加值或百分比时，先从通道合计中减去旧值，再加入新值。

### 重载堆

每个重载通道是一段最大二叉堆。比较规则是权重大者在前，权重相同则 Buff 实例 ID 大者在前。堆顶写入状态，公式只读堆顶。

插入和删除按 Buff 实例 ID 扫描该通道的堆段。堆调整只交换堆节点。堆节点不保存贡献下标。

增长时，如果这段堆不在缓冲末尾，就先把它复制到末尾，再追加空位，避免覆盖后面的堆。缓冲长度大于 32，且存活节点数不足缓冲长度的一半时，先把各通道仍然引用的堆段压紧。

### 工作区

每个 World 有一个带 `AttributeModifierWorkspace` 的实体，上面放三条缓冲：

| 缓冲 | 内容 |
| --- | --- |
| `AttributeModifierDirtyRef` | 本批待封存的单位和槽位。 |
| `AttributeModifierCalcInput` | 封存后的热字段快照。 |
| `AttributeModifierCalcResult` | 公式结果。 |

`EnsureWorkspace` 按 `World.SequenceNumber` 和实体是否仍存在缓存这个实体。序号变化或实体失效时才创建 `EntityQuery`。两个同时存在的 World 共用一个缓存槽，切换 World 时重新查找一次。

## 写入路径

`TrySetModifier` 在主线程完成下列步骤：

1. 校验 Buff 实例 ID、通道和值。
2. 用属性布局把属性 ID 二分成槽位。
3. 用 `states[slot]` 取得状态。
4. 扫描贡献缓冲，定位同一 Buff、同一槽位、同一通道的旧贡献。
5. 值和权重都相同则直接返回。该属性不进入脏列表。
6. 加值或百分比更新 128 位合计。重载则更新对应堆，并把新堆顶写入状态。
7. 状态从干净变为脏时，向工作区追加一条 `AttributeModifierDirtyRef`。同一属性在本批中再次修改时，脏标记已经为 1，不再追加。

删除按 Buff 实例倒序扫描贡献。每删一条都更新合计或堆，并对受影响的状态标脏一次。

写入不推迟到封存。查询和删除都要立刻看到当前贡献。一个 Buff 通常对每个通道只写一次，把多次设置攒到封存再合并，不能省掉这次定位。

128 位合计使用 `WideMath.SignedAccumulator`。加和减互为逆运算，包括 `long.MinValue`。合计本身不饱和。公式把合计收成阶段结果时才饱和，因此同一通道上多条贡献的合计与物理顺序无关。

## 批次

`UpdateOnce` 中的修改器部分就是 Seal、Calc、Apply。Access 在这次调用之外。系统组的完整顺序如下。

| 顺序 | 阶段 | 修改器相关的工作 |
| --- | --- | --- |
| 1 | `AttributeInputSealSystem` | 封存资源请求。不读取修改器。 |
| 2 | `AttributeModifierSealSystem` | 把脏属性的热字段抄成连续快照，并清除脏标记。 |
| 3 | `AttributeModifierCalcSystem` | 并行计算公式。只读快照。 |
| 4 | `AttributeModifierApplySystem` | 按单位写回属性，并为实际变化留下事件草稿。 |
| 5 | `AttributeRequestListenerSystemGroup` | 业务监听可以改资源请求。修改器不再改贡献。 |
| 6 | `AttributeCurrentValueApplySystem` | 应用资源当前值请求。 |
| 7 | `AttributeEventPublishSystem` | 排序草稿，分配本批 `EventId`，写出事件和 Tag。 |
| 8 | `AttributeEventConsumerSystemGroup` | 消费事件。此期间新写入的修改器进入下一次批次。 |
| 9 | `AttributeResolvedEventClearSystem` | 清空已发布的事件。 |

上表第 5 步到第 7 步是已经实现的请求监听和结算。下一代合同见 [属性请求流水线](属性请求流水线.md)。修改器的 Seal、Calc、Apply 不变。

### 封存

封存只遍历脏列表。每条记录用槽位直接取状态，把通道合计的高低字、重载堆顶和行为标记写入 `AttributeModifierCalcInput`，然后把该状态的脏标记清零。快照完成后清空脏列表。

封存不读取贡献缓冲，也不读取重载堆。封存之后的新设置留到下一次 `UpdateOnce`。

### 计算

计算把快照交给 Burst 的 `IJobParallelFor`，内循环批大小为 32。作业对每个下标调用 `AttributeModifierMath.Evaluate`，结果写入独立的 `NativeArray`。作业完成后，主线程把结果拷进工作区的结果缓冲。

这一阶段只产生 `NewBase` 和 `NewFinal`。它不写属性，也不写事件。

### 写回

写回先按单位的 `Index`、`Version` 和槽位排序，再把同一单位的连续结果分成一组。`IJobParallelFor` 的每个作业项处理一个单位，批大小为 1。同一单位的多个属性在该作业项内顺序写入。

动态缓冲不能由重叠的作业项同时写入。分组保证每个单位只出现在一个作业项中，因此查找使用 `NativeDisableParallelForRestriction`。

资源的 Current 缩放和 `[0, Max]` 限制在写回时进行，因为这两步需要旧的 Current 和 Max。数值和标记属性把 `NewFinal` 写入 Current。只有新旧值不同才追加重算草稿。草稿的 `RequestId` 为 0，`DeltaBits` 为 0，种类为 `Recalculated`。

发布阶段在每个单位内部按属性 ID、`RequestId` 排序，同一键下 Max 在 Current 之前。排序后的 `EventId` 从 1 连续编号，只在本批、本单位内有效。

## 性能选择

| 选择 | 作用 |
| --- | --- |
| 写入时维护通道合计和堆顶 | 批次只读热字段。贡献数量不进入计算作业。 |
| 128 位合计，公式处再饱和 | 加减可逆，合计与写入顺序无关。 |
| 状态与布局等长 | 设置、删除和封存都是 `states[slot]`，不扫描状态缓冲。 |
| 属性 ID 只在 API 边界二分 | 热路径使用槽位。 |
| 干净变为脏时才追加脏记录 | 同一属性本批多次修改只封存一次。 |
| 值与权重不变则不标脏 | 重复设置不产生快照和写回。 |
| 封存复制到连续的 `CalcInput` | 计算作业按数组下标读取，不随机访问单位缓冲。 |
| 计算与写回分开 | 计算没有结构写入。写回按单位分组，避免动态缓冲写冲突。 |
| 按 World 序号缓存工作区 | 每次标脏不再创建 `EntityQuery`。 |
| 堆调整只交换堆节点 | 上浮和下沉不回写贡献缓冲。 |
| 贡献缓冲不内联 | 单位块的大小不随贡献数量增长。 |
| 堆段过长且空洞过半时压紧 | 增长前的搬移不长期保留已删除节点。 |

## 保留的开销

这些成本是当前设计接受的：

- 定位一条贡献仍然扫描该单位的全部贡献。
- 定位一条重载仍然扫描该通道的堆段。
- 写回在当次 `UpdateOnce` 中 `Complete`，不把作业留到下一帧。
- 工作区缓存只有一个槽。同时使用两个 World 时，每次切换重新查找一次。
