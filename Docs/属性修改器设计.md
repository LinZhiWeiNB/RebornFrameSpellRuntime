# 属性修改器设计

本文说明修改器如何保存贡献、如何在一次属性批次中结算，以及这些选择针对哪些开销。

通道、公式和调用方式见 [属性修改器](属性修改器.md)。

## 目标

本管线是 Access → Resolve 架构。

| 阶段 | 执行位置 | 职责 |
| --- | --- | --- |
| Access | 主线程，两次批次之间 | 设置、查询、删除贡献，并维护各通道的当前值。 |
| Resolve | 主线程，或按单位并行 | 读取热记录和布局，计算基础值与最终值，写回属性，并为实际变化留下事件草稿。 |

流水线在两种 Resolve 之间选择：

- 主线程按脏列表逐槽结算。
- 按单位并行。同一单位的属性在同一个作业项里顺序写入。

`AttributeModifierResolveSelection.Select` 负责选择。当前每批都返回主线程。启用并行的判断留到真机测试之后再写入。测试可以把 `PreferredMode` 设成按单位并行，用来走另一条路径。

其余目标：

- 写入时维护每个通道的当前值。结算读取热记录，不遍历贡献。
- 公共方法接收属性 ID。内部按下标访问热记录。
- 查询立刻返回已保存的贡献。

一个 World 只有一条 `AttributePipeline`。系统使用 `DisableAutoCreation`，由 `UpdateOnce` 在主线程显式推进。`UpdateOnce` 运行 Resolve 以及批次中的请求和事件阶段。Access 不进入这次调用。批次期间不得禁用、销毁或回收已进入流水线的单位。结算完成之前不得再改通道值。

## 数据

### 热记录

`AttributeModifierChannels` 与单位属性布局等长，下标就是布局槽位。资源、数值和标记属性在 `InitializeUnit` 时各占一格。

热记录只保存结算要读的通道值：四个 128 位合计、三个重载堆顶，以及一个标志字节。标志字节包含三个重载非空位和脏位。配置基础值、值类型、行为、非负限制和资源缩放标记留在布局里，结算时按槽位读取。

设置和删除用 `channels[slot]` 定位。槽位超出热记录长度时写入失败。

### 重载堆位置

`AttributeModifierOverrideRange` 与热记录等长，下标相同。它记录三个重载堆在堆缓冲中的起点和长度。只有设置和删除会读写。结算不读这份缓冲。

### 贡献

`AttributeModifierContribution` 记录一条 `(槽位, Buff 实例 ID, 通道)` 的值和权重。该缓冲的 `InternalBufferCapacity` 为 0，贡献不内联进单位块。

查找一条贡献时，线性扫描该单位的贡献缓冲。替换加值或百分比时，先从通道合计中减去旧值，再加入新值。

### 重载堆

每个重载通道是一段最大二叉堆。比较规则是权重大者在前，权重相同则 Buff 实例 ID 大者在前。堆顶写入热记录，公式只读堆顶。

插入和删除按 Buff 实例 ID 扫描该通道的堆段。堆调整只交换堆节点。堆节点不保存贡献下标。

增长时，如果这段堆不在缓冲末尾，就先把它复制到末尾，再追加空位，避免覆盖后面的堆。缓冲长度大于 32，且存活节点数不足缓冲长度的一半时，先把各通道仍然引用的堆段压紧。

### 工作区

每个 World 有一个带 `AttributeModifierWorkspace` 的实体，上面放一条缓冲：

| 缓冲 | 内容 |
| --- | --- |
| `AttributeModifierDirtyRef` | 本批待结算的单位和槽位。 |

`EnsureWorkspace` 按 `World.SequenceNumber` 和实体是否仍存在缓存这个实体。序号变化或实体失效时才创建 `EntityQuery`。两个同时存在的 World 共用一个缓存槽，切换 World 时重新查找一次。

## 写入路径

`TrySetModifier` 在主线程完成下列步骤：

1. 校验 Buff 实例 ID、通道和值。
2. 用属性布局把属性 ID 二分成槽位。
3. 用 `channels[slot]` 取得热记录。
4. 扫描贡献缓冲，定位同一 Buff、同一槽位、同一通道的旧贡献。
5. 值和权重都相同则直接返回。该属性不进入脏列表。
6. 加值或百分比更新 128 位合计。重载则更新对应堆，并把新堆顶写入热记录。
7. 热记录从干净变为脏时，向工作区追加一条 `AttributeModifierDirtyRef`。同一属性在本批中再次修改时，脏标记已经为 1，不再追加。

删除按 Buff 实例倒序扫描贡献。每删一条都更新合计或堆，并对受影响的热记录标脏一次。

查询和删除立刻看到当前贡献。一个 Buff 通常对每个通道只写一次，多次设置仍在写入时定位并替换，由热记录保存替换后的合计或堆顶。

128 位合计使用 `WideMath.SignedAccumulator`。加和减互为逆运算，包括 `long.MinValue`。合计本身不饱和。公式把合计收成阶段结果时才饱和，因此同一通道上多条贡献的合计与物理顺序无关。

## 批次

`UpdateOnce` 中的修改器部分就是 `AttributeModifierResolveSystem`。Access 在这次调用之外。系统组的完整顺序如下。

| 顺序 | 阶段 | 修改器相关的工作 |
| --- | --- | --- |
| 1 | `AttributeInputSealSystem` | 封存资源请求。不读取修改器。 |
| 2 | `AttributeModifierResolveSystem` | 按脏列表计算并写回属性，为实际变化留下事件草稿，然后清空脏列表。 |
| 3 | `AttributeRequestListenerSystemGroup` | 业务监听可以改资源请求。这一阶段不修改贡献。 |
| 4 | `AttributeCurrentValueApplySystem` | 应用资源当前值请求。 |
| 5 | `AttributeEventPublishSystem` | 排序草稿，分配本批 `EventId`，写出事件和 Tag。 |
| 6 | `AttributeEventConsumerSystemGroup` | 消费事件。此期间新写入的修改器进入下一次批次。 |
| 7 | `AttributeResolvedEventClearSystem` | 清空已发布的事件。 |

### 结算

结算遍历本批开始时已经记下的脏槽。每条记录用槽位直接取热记录。脏标记为 0 的槽跳过。其余槽清掉脏标记，用布局中的配置基础值、值类型和非负限制调用 `AttributeModifierMath.Evaluate`，再把结果写入 `AttributeValueSlot`。

主线程版本按脏列表的现有顺序逐槽完成。按单位并行的版本先把脏槽按单位 `Index`、`Version` 和槽位排到一起，再让 `IJobParallelFor` 的每个作业项处理一个单位，批大小为 1。同一单位的多个属性在该作业项内顺序写入。

动态缓冲不能由重叠的作业项同时写入。分组保证每个单位只出现在一个作业项中，因此查找使用 `NativeDisableParallelForRestriction`。

资源的 Current 缩放和 `[0, Max]` 限制在写回时进行，因为这两步需要旧的 Current 和 Max。数值和标记属性把最终值写入 Current。只有新旧值不同才追加重算草稿。草稿的 `RequestId` 为 0，`DeltaBits` 为 0，种类为 `Recalculated`。

两条路径都在写回结束后清空脏列表。结算期间提交的新设置不进入本批。

发布阶段在每个单位内部按属性 ID、`RequestId` 排序，同一键下 Max 在 Current 之前。排序后的 `EventId` 从 1 连续编号，只在本批、本单位内有效。

## 性能选择

| 选择 | 作用 |
| --- | --- |
| 写入时维护通道合计和堆顶 | 结算只读热记录。贡献数量不进入结算。 |
| 热记录只保留合计、堆顶和标志 | 结算按槽位读取通道当前值。 |
| 重载堆位置单独存放 | 结算不触碰堆起点和长度。 |
| 128 位合计，公式处再饱和 | 加减可逆，合计与写入顺序无关。 |
| 热记录与布局等长 | 设置、删除和结算都是 `channels[slot]`，不扫描热记录。 |
| 属性 ID 只在 API 边界二分 | 热路径使用槽位。 |
| 干净变为脏时才追加脏记录 | 同一属性本批多次修改只结算一次。 |
| 值与权重不变则不标脏 | 重复设置不产生写回。 |
| 主线程与按单位并行共用同一套写回 | 两条路径的通道值和属性结果一致。 |
| 按单位分组后再并行 | 每个单位只出现在一个作业项中，动态缓冲不会被同时写入。 |
| 按 World 序号缓存工作区 | 每次标脏不再创建 `EntityQuery`。 |
| 堆调整只交换堆节点 | 上浮和下沉不回写贡献缓冲。 |
| 贡献缓冲不内联 | 单位块的大小不随贡献数量增长。 |
| 堆段过长且空洞过半时压紧 | 增长前的搬移不长期保留已删除节点。 |

## 保留的开销

这些成本是当前设计接受的：

- 定位一条贡献仍然扫描该单位的全部贡献。
- 定位一条重载仍然扫描该通道的堆段。
- 按单位并行在当次 `UpdateOnce` 中 `Complete`，不把作业留到下一帧。
- 工作区缓存只有一个槽。同时使用两个 World 时，每次切换重新查找一次。
