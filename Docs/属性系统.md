# 属性系统

## 架构

属性系统以 Unity Entities 的单位实体为运行时载体。全局属性定义与单位类型布局存放在只读 BlobAsset 中；单位只保存本单位的值、修改器、请求、Tag 和结算事件缓冲。

一个 World 只能创建一个 `AttributePipeline`。流水线不自动加入 Unity 更新循环，由上层帧同步显式调用 `UpdateOnce()`。

### 属性标识与定义

`AttributeId` 是 64 位标识：

```csharp
AttributeId id = AttributeId.Combine(authorId, localId);
```

- 高 32 位：作者 ID。
- 低 32 位：作者内部 ID。

`AttributeDefinition` 定义属性的值类型和行为：

- `AttributeValueKind.Int32`：32 位有符号整数。
- `AttributeValueKind.Int64`：64 位有符号整数。
- `AttributeValueKind.Fixed64`：Q32.32 定点数，使用 `FixedMathSharp.Fixed64`。
- `AttributeValueKind.Bool`：原始值只能为 0 或 1。

行为分为：

- `Resource`：拥有 `Current` 和 `Max`；请求只修改 `Current`，修改器计算 `Max`。
- `Numeric`：修改器计算 `Current`。
- `Marker`：使用覆盖修改器计算布尔或标记值。

`NonNegative != 0` 时，重算结果不得小于 0。`ScaleCurrentWithMax != 0` 时，资源 `Max` 变化会按原比例缩放 `Current`；无论是否缩放，`Current` 最终都限制在 `[0, Max]`。

### 目录、布局与单位

`AttributeCatalog.Build()` 校验、排序并冻结全局定义。`AttributeCatalog.BuildLayout()` 根据单位预设创建可由同类单位共享的布局。

```csharp
AttributeId health = AttributeId.Combine(0, 1);

BlobAssetReference<AttributeCatalogBlob> catalog = AttributeCatalog.Build(
    new[]
    {
        new AttributeDefinition
        {
            Id = health,
            ValueKind = AttributeValueKind.Int32,
            Behavior = AttributeBehavior.Resource,
            NonNegative = 1,
            ScaleCurrentWithMax = 1,
        },
    },
    Allocator.Persistent);

BlobAssetReference<AttributeLayoutBlob> layout = AttributeCatalog.BuildLayout(
    catalog,
    new[]
    {
        new UnitAttributePresetEntry
        {
            Id = health,
            DefaultValue = AttributeValue.FromInt32(100),
        },
    },
    Allocator.Persistent);

AttributeAccess.CreateCatalogSingleton(entityManager, catalog);
Entity unit = entityManager.CreateEntity();
AttributeAccess.InitializeUnit(entityManager, unit, layout);
```

`InitializeUnit()` 会一次性挂载流水线需要的组件和 DynamicBuffer。后续批次清空缓冲长度并复用容量，不反复增删组件。可通过重载传入 `IReadOnlyList<UnitResourceCurrentOverride>` 覆盖资源初始 `Current`；该覆盖会限幅且不产生事件。

BlobAsset 的生命周期由调用方管理。所有引用它们的 World 和实体停止使用后，再调用 `Dispose()`。

### 批次顺序

一次 `UpdateOnce()` 按以下顺序执行：

1. 将 Pending 修改器命令、请求和请求 Tag 封存到 Active 缓冲。
2. 应用修改器新增、更新和按 Buff 删除命令。
3. 每个 Dirty 属性统一重算并写回。
4. 执行 `AttributeRequestListenerSystemGroup` 中的业务监听系统。
5. 按顺序结算资源请求并发布 `AttributeResolvedEvent`。
6. 执行 `AttributeEventConsumerSystemGroup` 中的消费者，然后清空事件缓冲。

封存后提交的新命令或请求进入 Pending，只能在下一次 `UpdateOnce()` 处理。

`UpdateOnce()` 必须由上层帧同步在主线程、非重入地调用。单位只能在两次调用之间 Disabled、Destroy 或回收；不得在批次执行期间改变这些生命周期状态。监听器抛出的异常视为代码错误，流水线不提供事务回滚。

## 修改器 API

`AttributeModifierSpec` 唯一标识由 `(BuffInstanceId, ModifierLocalId)` 组成。

- `Channel.Base`：从单位默认值计算基础值。
- `Channel.Value`：从基础值计算最终值。
- `Operation.Add`：加上属性原始值。
- `Operation.Percent`：加上 Q32.32 百分比；同通道百分比先求和，再统一乘一次。
- `Operation.Override`：覆盖本通道算术结果；`Order` 较大者优先，相同 `Order` 时后提交者优先。

```csharp
var modifier = new AttributeModifierSpec(
    health,
    buffInstanceId: 1001,
    modifierLocalId: 0,
    AttributeModifierChannel.Value,
    AttributeModifierOperation.Add,
    valueBits: 20);

bool added = AttributeAccess.TryAddModifier(entityManager, unit, modifier);
bool updated = AttributeAccess.TryUpdateModifier(entityManager, unit, modifier);
bool removed = AttributeAccess.TryRemoveModifiersByBuff(
    entityManager,
    unit,
    buffInstanceId: 1001);
```

整数属性使用宽整数中间计算并在最终结果饱和。`Fixed64` 的加减乘除走第三方定点库；整数与定点原始位都不使用浮点数。

## CurrentValueRequest API

资源当前值通过请求修改：

```csharp
bool queued = AttributeAccess.TryRequestCurrentValueChange(
    entityManager,
    unit,
    health,
    deltaBits: -10);
```

另有单个 `TagId` 和 `NativeArray<TagId>` 原因 Tag 重载。API 会同步校验实体、布局、资源类型、原始值和配置 Tag；返回 `true` 仅表示成功进入 Pending，不表示最终一定应用。

每条成功入队的请求会获得单位内 `RequestId`。`RequestId` 为独立递增的 `ulong`，`0` 无效，`ulong.MaxValue` 的下一项为 `1`。Pending 转为 Active 时 ID 不变，缓冲清空也不会重置序列。

监听系统读取 `DynamicBuffer<AttributeCurrentValueRequest>`：

- `RequestId`、`AttributeId` 只读。
- `DeltaBits` 可写。
- Reason/Cancel Tag 通过同实体的 `DynamicBuffer<AttributeRequestTag>` 修改。

```csharp
foreach (var (requests, tags) in SystemAPI.Query<
             DynamicBuffer<AttributeCurrentValueRequest>,
             DynamicBuffer<AttributeRequestTag>>())
{
    for (int i = 0; i < requests.Length; i++)
    {
        AttributeCurrentValueRequest request = requests[i];
        request.DeltaBits /= 2;
        requests[i] = request;

        AttributeRequestTags.TryAdd(
            tags,
            request.RequestId,
            AttributeRequestTagSet.Reason,
            reducedTag);
    }
}
```

请求按固定优先级结算：

1. 目标或布局错误：`RequestRejected`。
2. 最终 Cancel Tag 非空：`RequestCancelled`。
3. 最终 `DeltaBits` 超出属性类型范围：`RequestRejected`。
4. 归一化和限幅后未变化：`RequestNoChange`。
5. 实际写回：`RequestApplied`。

每条 Active 请求恰好产生一条结果事件。非 Applied 结果满足 `NewBits == OldBits`。

## AttributeResolvedEvent API

`DynamicBuffer<AttributeResolvedEvent>` 只在事件消费窗口内有效：

- `EventId`：单位内事件序列；规则与 RequestId 相同，但两个序列互相独立。
- `RequestId`：来源请求 ID；修改器重算事件为 0。
- `Kind`：`Recalculated`、`RequestApplied`、`RequestCancelled`、`RequestNoChange` 或 `RequestRejected`。
- `AttributeId`、`ValueKind`、`Target`：事件目标。
- `DeltaBits`：监听结束后的请求变化量；重算事件为 0。
- `OldBits`、`NewBits`：结算前后值。

修改器重算只在值实际变化时产生 `Recalculated` 事件。资源 Max 与 Current 都发生变化时，会分别产生事件。

```csharp
foreach (var (events, eventTags) in SystemAPI.Query<
             DynamicBuffer<AttributeResolvedEvent>,
             DynamicBuffer<AttributeResolvedEventTag>>())
{
    for (int i = 0; i < events.Length; i++)
    {
        AttributeResolvedEvent resolved = events[i];
        bool recalculated = AttributeRequestTags.EventContains(
            eventTags,
            resolved.EventId,
            AttributeRequestTagSet.Reason,
            LibraryTags.Recalculation);
    }
}
```

`EventId` 和 `RequestId` 只在所属单位当前运行期内稳定。跨单位记录必须同时保存单位稳定 ID；它们不应作为永久历史全局 ID。

## 读取与生命周期

```csharp
if (AttributeAccess.TryRead(entityManager, unit, health, out AttributeSnapshot value))
{
    long current = value.CurrentBits;
    long max = value.MaxBits;
}
```

`AttributePipeline.Dispose()` 只销毁它创建的系统，不销毁 World。每个 World 只能创建一个流水线实例。
